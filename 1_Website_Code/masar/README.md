# مسار | Masar

منصة توجّه الطالب إلى المسار التقني المناسب له: يجيب عن أسئلة تحديد المسار، ثم يختبر مستواه، ثم يحصل على خطة تطوير ومهام عملية يسلّمها ويراجعها المشرف. الموقع بالعربية والإنجليزية.

**المسارات:** UI/UX، Front-end، Back-end، Data.
**التقنيات:** React + Vite (الواجهة)، Node.js + Express (الخادم)، MongoDB + Mongoose (قاعدة البيانات).

---

## التشغيل على جهازك

**المطلوب:** Node.js 20 أو أحدث، و MongoDB (محليًا أو حساب مجاني على MongoDB Atlas).

### 1. الخادم

```bash
cd server
npm install
cp .env.example .env      # ثم عدّل MONGO_URI و JWT_SECRET
npm run create-admin      # ينشئ حساب المشرف من بيانات ADMIN_* في .env
npm run dev               # يعمل على http://localhost:5000
```

### 2. الواجهة (في نافذة أخرى)

```bash
cd client
npm install
npm run dev               # يعمل على http://localhost:5173
```

افتح `http://localhost:5173`. أثناء التطوير تتحول طلبات `/api` تلقائيًا إلى الخادم على المنفذ 5000.

### 3. الاختبارات

```bash
cd server
npm test                                                    # بدون قاعدة بيانات
MONGO_URI_TEST=mongodb://127.0.0.1:27017/masar_test npm test   # الرحلة الكاملة على قاعدة اختبار فارغة
```

الجزء الثاني يمسح قاعدة الاختبار في البداية والنهاية، فلا تستخدم معه قاعدة البيانات الحقيقية.

## نسخة العرض (ملف واحد بدون سيرفر)

`npm run build:demo` من داخل `client` يبني `client/dist-demo/Masar_Demo.html`: الموقع كله في ملف واحد يفتح بدبل كليك، مع نسخة من الـ API تعمل داخل المتصفح (`client/demo/`) وتستخدم نفس ملفات المحتوى ونفس كود الحساب الموجود في السيرفر. البيانات تُحفظ في المتصفح فقط، وتبدأ بمشرف (`admin@masar.test` / `admin1234`) وعشرة طلاب تجريبيين. للعرض فقط، وليست بديلًا عن النشر.

## مزايا تجربة الطالب

- **حفظ التقدم في الأسئلة:** إجابات أسئلة المسار واختبار المستوى تُحفظ في المتصفح أثناء الحل، فلو أُغلقت الصفحة يكمل الطالب من نفس السؤال. تُمسح بعد التسليم الناجح (`client/src/quizProgress.js`).
- **مراجعة قبل التسليم:** بعد آخر سؤال تظهر شبكة بأرقام الأسئلة للرجوع لأي سؤال، مع توضيح أن الإعادة ممكنة وأن آخر نتيجة هي المعتمدة.
- **إشعار برد المشرف:** رقم على «المهام» في القائمة وعلامة «رد جديد» على المهمة، تختفي عند فتح المهام (`GET /api/me/notifications` و`POST /api/me/notifications/seen`).
- **ترحيب للطالب الجديد:** صفحة «رحلتي» تعرض ثلاث خطوات وزرًا واحدًا بدل عدادات فارغة.
- **لوحة الإدارة:** قوائم الطلاب والتسليمات مقسمة لصفحات (`?page=&pageSize=`، 20 افتراضيًا)، والتسليمات تفتح على «قيد المراجعة».
- **أين يتوقف الطلاب؟** في نظرة عامة: عدد من وصل إلى كل محطة (سجّل، أسئلة المسار، اختبار المستوى، سلّم مهمة، اعتُمدت له مهمة) مع تحديد أكبر توقف.
- **طلاب بلا نشاط:** من لم يدخل المنصة منذ 7 أيام ولم تُعتمد له مهمة. يظهر عددهم في نظرة عامة مع زر يعرض أسماءهم (`/admin/students?quiet=1`)، وعمود «آخر نشاط» في قائمة الطلاب وفي ملف CSV. وقت آخر نشاط يُحدَّث مرة واحدة في الساعة على الأكثر لكل طالب.
- **تفاصيل الطالب للمشرف:** آخر نشاط، وتاريخ التسجيل، وكم خطوة أنهى من خطته، ومهمته التالية.

### ما يشجع الطالب على الإكمال

بدون نقاط ولا مسابقات، فقط إحساس واضح بالتقدم:

- **شريط التقدم خط مترو صغير:** كل سؤال محطة تمتلئ عند الإجابة، و«قطار» يتحرك مع السؤال الحالي (`QuestionRunner.jsx`).
- **رسائل في منتصف الطريق وقبل النهاية:** «وصلت إلى منتصف الطريق»، «بقيت 3 أسئلة فقط»، «السؤال الأخير».
- **انتقال تلقائي في أسئلة المسار:** الضغط بالماوس أو اللمس ينتقل للسؤال التالي بعد لحظة، أما لوحة المفاتيح فلا تنتقل حتى يتحرك الطالب بالأسهم بحرية.
- **كشف النتيجة:** النسب تعدّ من الصفر والأشرطة تمتلئ بالتتابع، وقارئ الشاشة يسمع الرقم النهائي مباشرة (`CountUp.jsx`).
- **«لماذا هذا المسار؟»:** ثلاث إجابات من إجابات الطالب نفسه هي الأقوى في ترجيح المسار (`explainTrack` في `scoring.js`).
- **احتفال بالشارة:** بطاقة صغيرة عند الحصول على شارة جديدة مع الخطوة التالية، تُغلق وحدها بعد 6 ثوانٍ وتبقى إذا وقف عليها المؤشر. تظهر مرة واحدة فقط لكل شارة.
- **قائمة خطوات الخطة:** يعلّم الطالب كل خطوة أنهاها، وتُحفظ في حسابه (تعمل من أي جهاز) مع حلقة تقدم ورسالة عند إنهاء الخطة.
- **الخطوة التالية بوقت تقريبي:** «نحو 10 دقائق» لاختبار المستوى، ويحسب الوقت المتبقي إن كان الطالب بدأ ولم يكمل. بعد الاختبار تقترح المهمة التالية، وتقدّم المهمة التي طلب المشرف تعديلها.
- **هياكل تحميل بدل الدوامة:** شكل الصفحة يظهر رماديًا أثناء التحميل (بعد 220ms فقط حتى لا يومض).
- **حالات فارغة برسم خط مترو:** للمهام قبل اختيار المسار، ولوحة الإدارة بلا تسليمات، وصفحة غير موجودة.

كل الحركة تتوقف لمن فعّل «تقليل الحركة» في نظامه، والأرقام تظهر نهائية مباشرة.

## طريقة الحساب (فريق Data)

**أسئلة المسار:** كل اختيار يعطي 3 نقاط لمساره الأساسي، وأحيانًا نقطة لمسار قريب منه. نسبة التوافق مع أي مسار = النقاط التي حصل عليها ÷ أعلى نقاط ممكنة له (45). المسار صاحب أعلى نسبة هو المقترح. لو الفرق بين أول مسارين أقل من 10%، تظهر للطالب رسالة أن المسارين متقاربان.

**اختبار المستوى:** 15 سؤالًا (5 سهلة، 5 متوسطة، 5 صعبة). الوزن: سهل 1، متوسط 2، صعب 3، والمجموع 30.

| النسبة الموزونة | المستوى |
|---|---|
| أقل من 50% | مبتدئ |
| من 50% إلى 79% | متوسط |
| 80% فأكثر | متقدم |

لتغيير النسب أو الأوزان عدّل `LEVELS` و `DIFFICULTY_WEIGHTS` في `scoring.js`، ثم شغّل `npm test`.

## تعديل المحتوى

- كل نص له نسختان: `"ar"` و `"en"`.
- ضع الكود داخل علامتي `` ` `` ليظهر بشكل صحيح وسط الجمل العربية، مثل: ``"ما نتيجة `typeof []`؟"``.
- في اختبار المستوى: `answer` هو رمز الإجابة الصحيحة (`a` أو `b` أو `c` أو `d`). الخادم يخلط ترتيب الاختيارات عند العرض، ولا يرسل الإجابات الصحيحة للمتصفح.
- كل مسار له 6 مهام (2 لكل مستوى) وخطة لكل مستوى.
- لكل خطوة في الخطة `id` ثابت (`s1`، `s2`...). لا تغيّره بعد النشر، لأن علامات «أنهيت هذه الخطوة» محفوظة به في حسابات الطلاب. خطوة جديدة تأخذ رقمًا جديدًا.
- بعد أي تعديل شغّل `npm test` داخل `server` للتأكد أن الملفات سليمة.

## واجهة الخادم (API)

كل الطلبات تبدأ بـ `/api`. الطلبات المحمية تحتاج `Authorization: Bearer <token>`.

| الطريقة | المسار | الوصف |
|---|---|---|
| POST | `/auth/register` | إنشاء حساب |
| POST | `/auth/login` | تسجيل الدخول |
| GET | `/auth/me` | بيانات المستخدم الحالي |
| GET | `/tracks` | المسارات |
| GET | `/track-quiz` | أسئلة تحديد المسار (بدون النقاط) |
| POST | `/track-quiz/submit` | تسليم الإجابات وحساب المسار |
| PUT | `/me/track` | اختيار مسار |
| GET | `/tracks/:track/level-test` | أسئلة اختبار المستوى (بدون الإجابات) |
| POST | `/tracks/:track/level-test/submit` | تسليم الاختبار وحساب المستوى |
| GET | `/tracks/:track/tasks` | مهام المسار مع تسليمات الطالب |
| POST | `/tasks/:taskId/submissions` | تسليم مهمة أو إعادة تسليمها |
| GET | `/me/progress` | تقدم الطالب |
| GET | `/me/plan` | خطة التطوير حسب المسار والمستوى، مع الخطوات المنجزة (`done`). قبل اختيار المسار أو اختبار المستوى يرجع `{ "needs": "track" }` أو `{ "needs": "level" }` |
| PUT | `/me/plan/steps/:stepId` | تعليم خطوة من الخطة كمنجزة أو إلغاؤها (`{ "done": true }`) |
| GET | `/me/notifications` | ردود المشرف غير المقروءة والشارات المكتسبة |
| POST | `/me/notifications/seen` | تعليم ردود المشرف كمقروءة |
| GET | `/admin/stats` | إحصاءات، ومحطات الطلاب (`funnel`)، وعدد من بلا نشاط منذ أسبوع (`quiet`) (مشرف) |
| GET | `/admin/students` | قائمة الطلاب مع البحث، و`?quiet=1` لمن بلا نشاط (مشرف) |
| GET | `/admin/students/:id` | تفاصيل طالب مع تقدمه في الخطة (`plan`) (مشرف) |
| GET | `/admin/submissions` | التسليمات حسب الحالة والمسار (مشرف) |
| PATCH | `/admin/submissions/:id` | اعتماد تسليم أو طلب تعديل (مشرف) |

الأخطاء ترجع بالشكل `{ "error": { "code": "...", "message": "..." } }`، والواجهة تترجم `code` للعربي أو الإنجليزي.

## الرفع على الإنترنت

أسهل طريقة: خدمة واحدة على Render تشغّل الخادم وتعرض الواجهة معًا.

1. أنشئ قاعدة بيانات مجانية على **MongoDB Atlas** وانسخ رابط الاتصال.
2. ارفع المشروع على GitHub.
3. على **Render** أنشئ Web Service من المستودع بالإعدادات التالية:
   - **Build Command:** `cd client && npm install --include=dev && npm run build && cd ../server && npm install`
   - **Start Command:** `cd server && npm start`
   - **Environment:** `MONGO_URI`، `JWT_SECRET` (نص طويل عشوائي)، `NODE_ENV=production`
4. لإنشاء حساب المشرف: ضع رابط Atlas في `MONGO_URI` داخل `.env` على جهازك، ثم شغّل `npm run create-admin` من مجلد `server`.

لو أردتم رفع الواجهة منفصلة (Vercel أو Netlify): ضعوا `VITE_API_URL` برابط الخادم في إعدادات الواجهة، وأضيفوا رابط الواجهة إلى `CLIENT_URL` في إعدادات الخادم.
