# نشر مسار على الإنترنت

الطريقة الموصى بها: **خدمة واحدة على Render** تبني واجهة React وتشغّل الخادم الذي يقدّمها، مع قاعدة بيانات مجانية على **MongoDB Atlas**. كل الخطوات مجانية ولا تحتاج بطاقة ائتمان.

الوقت المتوقع: 30 دقيقة.

---

## 1. قاعدة البيانات (MongoDB Atlas)

1. أنشئ حسابًا على [mongodb.com/atlas](https://www.mongodb.com/atlas) وأنشئ **Cluster** مجانيًا (M0). اختر أقرب منطقة (مثل Frankfurt).
2. من **Database Access** أنشئ مستخدمًا لقاعدة البيانات: اسم وكلمة مرور قوية (احفظهما).
3. من **Network Access** اضغط **Add IP Address** ثم **Allow access from anywhere** (`0.0.0.0/0`)، لأن عنوان Render يتغير.
4. من **Connect > Drivers** انسخ رابط الاتصال. سيكون بهذا الشكل:
   ```
   mongodb+srv://USER:PASSWORD@cluster0.xxxxx.mongodb.net/masar?retryWrites=true&w=majority
   ```
   ضع اسم المستخدم وكلمة المرور مكان `USER` و`PASSWORD`، وتأكد أن اسم قاعدة البيانات `masar` موجود بعد `/`.

> لو كلمة المرور فيها رموز مثل `@` أو `#` فاكتبها بصيغة URL (مثلًا `@` تصبح `%40`).

## 2. الكود على GitHub

1. أنشئ مستودعًا (repository) خاصًا على GitHub اسمه `masar`.
2. ارفع مجلد المشروع كله (بدون `node_modules`). الملف `.gitignore` يستثنيها تلقائيًا.

## 3. الخادم والموقع (Render)

1. أنشئ حسابًا على [render.com](https://render.com) بحساب GitHub.
2. اضغط **New > Blueprint** واختر مستودع `masar`. سيقرأ Render ملف `render.yaml` ويجهّز الخدمة.
3. سيطلب منك القيم التالية:

   | المتغير | القيمة |
   |---|---|
   | `MONGO_URI` | رابط الاتصال من الخطوة 1 |
   | `CLIENT_URL` | عنوان الخدمة نفسها، مثل `https://masar.onrender.com` (ستعرفه من اسم الخدمة) |
   | `ADMIN_NAME` | اسم المشرف |
   | `ADMIN_EMAIL` | بريد المشرف |
   | `ADMIN_PASSWORD` | كلمة مرور المشرف (8 أحرف على الأقل) |

   `JWT_SECRET` يولَّد تلقائيًا، و`NODE_ENV` مضبوط على `production`.
4. اضغط **Apply**. أول بناء يستغرق 3–5 دقائق. عندما يظهر **Live** افتح العنوان.
5. عند أول تشغيل ينشئ الخادم حساب المشرف تلقائيًا من `ADMIN_*` إن لم يكن موجودًا. سجّل الدخول به ثم غيّر كلمة المرور من صفحة **حسابي**.

### التحقق

- `https://اسم-الخدمة.onrender.com/api/health` يجب أن يعيد `{"ok":true,"db":"connected"}`.
- أنشئ حساب طالب تجريبيًا وأكمل الرحلة كلها من الهاتف.
- افتح أدوات المطور في Chrome، تبويب **Lighthouse**، واختر Mobile ثم Analyze على الصفحة الرئيسية. القيم المتوقعة (من تجربة نسخة الإنتاج نفسها): الأداء 97 تقريبًا، وإمكانية الوصول وأفضل الممارسات وSEO كلها 100. لو جاء الأداء أقل بكثير فغالبًا الخادم كان نائمًا؛ أعد التحليل.
- `https://اسم-الخدمة.onrender.com/robots.txt` يفتح ملف النص (صفحات الطلاب والمشرف ممنوعة من محركات البحث عن قصد).

### ما يفعله الخادم للسرعة تلقائيًا

- يضغط كل الردود (gzip)، فملف التطبيق الأساسي ينزل بنحو ثلث حجمه.
- ملفات `/assets` تحمل بصمة في أسمائها، فيحفظها المتصفح سنة كاملة، و`index.html` يُفحص في كل زيارة فيظهر أي تحديث فورًا.
- React في ملف منفصل لا يتغير مع تحديثات التطبيق، فالطالب العائد لا يعيد تنزيله.
- الخطان الأساسيان (العربي واللاتيني) يُحمَّلان مبكرًا حتى لا يقفز النص عند ظهور الخط.

### ملاحظة عن الخطة المجانية

الخدمة المجانية تنام بعد 15 دقيقة بلا استخدام، وأول طلب بعدها يستغرق نحو 30–60 ثانية. هذا طبيعي. لو أزعج الطلاب، فخطة Render المدفوعة الأصغر (7 دولارات شهريًا) تمنع ذلك.

## 4. التحديثات لاحقًا

أي `git push` إلى الفرع الرئيسي يعيد بناء الموقع ونشره تلقائيًا خلال دقائق. لتعديل الأسئلة أو المهام عدّل ملفات `server/src/content/` وشغّل `npm test` قبل الرفع.

## 5. النسخ الاحتياطي

- Atlas المجاني لا يعمل نسخًا احتياطيًا تلقائيًا. مرة كل أسبوع صدّر النتائج من لوحة الإدارة (ملف CSV)، أو استخدم أداة `mongodump` على جهازك:
  ```bash
  mongodump --uri="رابط الاتصال" --out=backup-$(date +%F)
  ```

## 6. حل المشكلات

| العرض | السبب المرجح | الحل |
|---|---|---|
| الخدمة تفشل عند البدء وفي السجل `Could not connect to MongoDB` | رابط `MONGO_URI` خطأ أو IP غير مسموح | راجع الخطوة 1 (كلمة المرور وNetwork Access) |
| `JWT_SECRET must be a random string` | السر قصير | استخدم قيمة من 32 حرفًا فأكثر |
| الموقع يفتح لكن تسجيل الدخول يفشل من نطاق آخر | `CLIENT_URL` لا يطابق عنوان الموقع | ضع العنوان الكامل بدون `/` في النهاية |
| نسيت كلمة مرور المشرف | — | غيّر `ADMIN_PASSWORD` في Render لن يكفي؛ احذف حساب المشرف من Atlas (مجموعة `users`) ثم أعد تشغيل الخدمة لينشئه من جديد |

## بديل: الواجهة على Vercel والخادم على Render

مناسب لو أردت الواجهة أسرع في الفتح (لا تنام). الفرق:

1. على Render أنشئ **Web Service** من مجلد `server` فقط: Build `npm install`، Start `npm start`، ونفس المتغيرات أعلاه، لكن `CLIENT_URL` = عنوان Vercel.
2. على [vercel.com](https://vercel.com) استورد المستودع، واختر **Root Directory** = `client`، وأضف متغير `VITE_API_URL` = عنوان خدمة Render (بدون `/api`).
3. أضف ملف `client/vercel.json` التالي ليعمل التنقل داخل التطبيق:
   ```json
   { "rewrites": [{ "source": "/(.*)", "destination": "/index.html" }] }
   ```

## بديل: Docker

`Dockerfile` في جذر المشروع يبني كل شيء في صورة واحدة. يصلح لأي استضافة تقبل Docker (Railway، Fly.io، خادم خاص):

```bash
docker build -t masar .
docker run -p 5000:5000 --env-file server/.env masar
```
